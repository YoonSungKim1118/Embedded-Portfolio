# rs485-frame

반이중 시리얼 스트림에서 프레임을 잘라내는 수신기. C99, 동적 할당 없음.

```
+------+------+------+------+----------+---------+
| STX  | ADDR | CMD  | LEN  | DATA[..] | CRC16   |
| 0x02 | 1B   | 1B   | 1B   | LEN B    | 2B (LE) |
+------+------+------+------+----------+---------+
  CRC 범위 : ADDR ~ DATA 끝 (STX 제외), CRC-16/MODBUS
```

```bash
make test
```

---

## 왜 상태머신이 아니라 슬라이딩 윈도우인가

교과서적인 수신기는 `IDLE → HEADER → PAYLOAD → CRC` 상태머신으로 만든다.
코드가 짧고 버퍼도 필요 없다. 그런데 이 구조에는 한 가지 약점이 있다.

**데이터 안에 STX 와 같은 값(0x02)이 들어 있으면 가짜 헤더를 붙잡는다.**
한 번 헤더를 확정하면 길이 필드만 믿고 그만큼을 삼키기 때문에,
잡음 바로 뒤에 붙어 온 진짜 프레임까지 함께 버려진다.
바이너리 데이터를 싣는 프로토콜에서는 드문 일이 아니다.

여기서는 받은 바이트를 프레임 한 개 크기(261B) 버퍼에 쌓고,
버퍼 앞에서 온전한 프레임을 찾는다. 후보의 CRC 가 틀리면
**맨 앞 한 바이트만 버리고 같은 버퍼를 다시 훑는다.**
가짜 STX 였다면 다음 바이트부터 다시 맞춰진다.

대가는 버퍼 261바이트와 CRC 재계산이다.
프레임이 초당 수천 개씩 오는 구간이 아니라면 그만한 값을 한다.

## 길이 필드만으로는 닫히지 않는 경우

재동기에도 한계가 있다. **잡음이 길이 필드를 크게 만들면** 수신기는
오지 않을 바이트를 기다리며 멈춘다. 버퍼 안에서 후보가 완결되지 않으니
CRC 를 볼 기회 자체가 없다.

`tests/test_stx_inside_payload` 의 두 번째 경우가 그것이다.
잘린 프레임 뒤에 온전한 프레임이 **틈 없이** 이어 오면 풀리지 않는다.

그래서 시간 기준을 하나 더 둔다. 바이트 사이가 `gap_ms` 이상 벌어지면
수집 중이던 버퍼를 통째로 버린다. Modbus RTU 의 t3.5 와 같은 개념이다.
실제 버스에서는 프레임 사이에 반드시 무음 구간이 있으므로 이것으로 닫힌다.

정리하면 **CRC 재동기는 버퍼 안에서 완결되는 오류를, 무음 타이머는
길이 필드가 깨진 오류를** 각각 맡는다. 둘 다 있어야 한다.

`gap_ms = 0` 으로 두면 타이머를 쓰지 않는다 (호스트 시험용).

## API

```c
rs485_rx_t rx;
rs485_rx_init(&rx, 10);                    /* 10ms 무음이면 버린다 */

/* 수신 인터럽트 또는 폴링 루프에서 */
if (rs485_rx_push(&rx, byte, now_ms)) {
    /* rx.frame 이 유효하다. 다음 push 전에 처리한다. */
    handle(rx.frame.addr, rx.frame.cmd, rx.frame.data, rx.frame.len);
}

/* 바이트가 없는 동안 주기적으로 */
rs485_rx_tick(&rx, now_ms);

/* 송신 */
uint8_t out[RS485_MAX_FRAME];
size_t  n = rs485_build(out, sizeof(out), addr, cmd, data, len);
```

진단용 카운터를 함께 쌓는다.

| 항목 | 뜻 |
|---|---|
| `frames_ok` | CRC 까지 통과한 프레임 |
| `crc_error` | CRC 불일치로 버린 후보 |
| `discarded_bytes` | 동기를 맞추며 버린 바이트 |
| `timeouts` | 무음 구간으로 비운 미완성 버퍼 |
| `overflows` | 버퍼가 가득 차 강제로 민 횟수 |

현장에서 "가끔 안 된다"는 신고가 들어왔을 때, 이 네 숫자의 비율만 봐도
원인이 배선인지 타이밍인지 상대 장비인지 절반은 갈린다.

## 함께 들어 있는 것

- `ringbuf` — 단일 생산자/소비자 바이트 링버퍼.
  용량을 2의 거듭제곱으로 고정해 나눗셈 없이 인덱스를 감싼다.
  가득 차면 **새 데이터를 버린다.** 오래된 것을 덮어쓰면 수집 중이던
  프레임의 앞부분이 깨져 복구가 더 어려워지기 때문이다.
- `crc16` — CRC-16/MODBUS. 256바이트 테이블을 쓸 여유가 없는 MCU 를
  전제로 비트 단위로 계산한다. 표준 검사값(`"123456789"` → `0x4B37`)으로 확인한다.

## 시험

외부 프레임워크 없이 264개 검사를 돌린다.

- 링버퍼 경계 — 가득 참 / 빔 / 인덱스 한 바퀴
- CRC 표준 검사값, 누적 갱신과 일괄 계산의 일치
- 빌드 ↔ 파싱 왕복, 길이 0 프레임, 출력 버퍼 부족
- 앞에 잡음이 깔린 경우
- 가짜 헤더 뒤 재동기 (타이머 없이)
- 데이터에 STX 가 들어 있는 프레임
- 무음 구간 타임아웃과 그 뒤의 정상 수신

`-Wall -Wextra -Wpedantic -Wconversion` 경고 없이 빌드된다.
